## Этап 0. Тестовая обвязка — без неё нечем закрепить остальное

Тестов у фронтенда нет, CI выполняет только `node --check`. Обвязка проверена в деле: страница — один
конкатенированный скрипт в общей области, поэтому тест загружает нужные файлы в свой контекст через
`vm.runInThisContext` в порядке `APP_JS_PARTS`; из браузера нужны ровно две заглушки (`window.localStorage`,
`document.currentScript/getElementById`). Пробный тест уже проходит и уже фиксирует три дефекта ниже.

- [x] `tests/frontend/harness.mjs` — `load(...files)` + `stubBrowser()` (28 строк).
- [x] `scripts/check-js.sh` — `node --test tests/frontend/*.test.mjs` после `node --check`.
- [x] Тесты написаны вместе с исправлениями этапа 1: 13 тестов в 5 файлах.

Оценка: 1 ч. Риск: нулевой, новый код не попадает в бандл.

## Этап 1. Пять багов, которые видит пользователь

Каждый — с тестом на чистой функции, который падает до исправления.

- [x] **Выдуманный адрес** (проверено). `validator_identity.js:4` + `format_addresses.js:30`: без кошелька
      в таблицу «недавно отсутствующих» идёт `public_key`, а `formatMasterchainAddress` превращает любой
      64-hex в `-1:<hex>`, на TON — в правдоподобный `EQ…`. Несуществующий адрес показан, подписан
      «EVER address» и копируется кнопкой.
      *Как делать:* при откате к публичному ключу не прогонять его через адресное форматирование —
      показывать `shortenHash`, копировать сырой hex, подпись «Public key».
      *Тест:* `formatDisplayAddress` не должна принимать 64-hex за адрес; ячейка отдаёт hex как значение копии.
- [x] **Ноль показывается как «–»** (проверено). `format_numbers.js:6`: `sumTokenValues` возвращает `""`
      при нулевой сумме. *Как делать:* возвращать `"0"`, оставив `""` только для пустого списка.
      *Тест:* сумма `[0]` → `"0"`, сумма `[]` → `""`.
- [x] **Фаза «After elections» недостижима** (проверено на живых данных). `clock_model.js:12`: `electionShift`
      сдвигает окно на раунд, как только `now > rawElectionsEnd`. Сейчас у TON `next_set` уже известен, и
      панель пишет «Elections start in 10.77 ч», хотя раунд сменится через 1.67 ч.
      *Как делать:* сдвигать окно по границе раунда, а не по концу выборов; когда `next_set` известен —
      это и есть «After elections», отсчёт вести до смены раунда.
      *Тест:* три фазы при `next_set = null` и при заполненном, включая границы.
- [x] **Выборы открыты, кандидатов нет → «waiting / No validators announced»** (проверено). `rounds.js:77`.
      *Как делать:* отдельная ветка «elections open, no candidates yet» до падения в «ожидание».
- [x] **Тултип и глоссарий остаются висеть** (проверено). `validator_tooltips.js:136`,
      `validator_type_glossary.js:126`: `rounds.js` делает `replaceChildren()` на каждом опросе,
      `mouseleave` не приходит. *Как делать:* звать `hideValidatorTooltip()` и `closeValidatorTypeGlossary()`
      в начале `renderRoundPanels` (как уже делает `node_stats_tables.js:18`).
- [x] **Любая ошибка статистики = «Statistics are unavailable»** (проверено). `round_stats_charts.js:46`:
      ветка `includes("timeout")` недостижима. *Как делать:* смотреть `error.name === "TimeoutError"` и
      подстроку `"timed out"`.
- [x] **Один тип контракта — три бейджа** (проверено). `validator_type_model.js:9`: DePoolProxy с узнанным
      хешем → DEPOOL, с неузнанным → UNKNOWN, без хеша → PROXY; для PROXY/StPROXY нет статьи в глоссарии.
      *Как делать:* бейдж по собственному типу контракта, состояние хеша источника — в тултипе;
      добавить недостающие статьи. *Тест:* один `contract_type` → один бейдж при любом хеше.

Оценка: 4–5 ч. Риск: низкий, всё локально.

## Этап 2. Смена сети и карта

- [x] **Точки прежней сети под новым заголовком** (проверено). `map_features.js:2` читает `validatorMapNodes`
      без проверки `validatorMapNodesChainId`, хотя `node_stats.js:164` и `map_controls.js:220` проверяют;
      `map_controls.js:166` при смене сети не чистит источник. *Как делать:* один аксессор
      `currentChainMapNodes()` с проверкой внутри — и убрать разнобой из трёх мест.
- [x] **«No mapped validators» вместо загрузки** (проверено). `node_stats.js:99`: `renderNodeStats()` после
      обновления без проверки снапшота (у кэш-пути проверка есть).
- [x] **У карты нет обработчика `error`** (проверено). `map_render.js`: есть `load`/`click`/`contextmenu`,
      нет `on("error")`; «Loading map» снимается по загрузке скриптов, до стиля и тайлов — сломанная карта
      выглядит пустой. *Как делать:* повесить `map.on("error")` на статус-строку, снимать «Loading map»
      по событию `load` стиля.
- [x] **`200` с не-JSON телом рушит загрузку** (проверено). `api.js:18` → `{}` → `runtime_chains.js:5`
      бросает TypeError → `app.js:33` бросает второй уже внутри `catch` → ретрай не планируется.
      *Как делать:* `fetchJson` бросает внятную ошибку вместо `{}`; в `catch` проверять `Array.isArray`.

Оценка: 3 ч.

## Этап 3. Стоимость рендера

- [x] **Одна строка — половина эффекта** (проверено). `runtime_clock.js:73`: `state.roundRenderKey = null`
      безусловно на каждом успешном опросе. Клиент опрашивает раз в 30 с, сервер обновляется раз в 60 с и
      отвечает `304` — но обе таблицы раундов сносятся и строятся заново для байт-идентичного снапшота.
      Ключ в `rounds.js:2-11` уже учитывает всё нужное. *Как делать:* убрать строку; при необходимости
      сравнить `fetched_at` с уже сохранённым и выйти раньше.
- [x] **Часы пересобираются целиком каждую секунду** (проверено). `clock.js:7`: `svg.replaceChildren()` и
      ~150 узлов плюс блок `defs` с 8 `feDropShadow` — раз в секунду. *Как делать:* статическую геометрию и
      `defs` строить один раз, за тик менять только `transform` стрелки и атрибуты дуги.
- [x] **Секундный таймер не гасится в скрытой вкладке** (проверено). `runtime.js:26`: `whenVisible` обёрнут
      только вокруг `refreshStaleSnapshot`. *Как делать:* обернуть весь `renderNow`, дорисовывать при возврате.
- [x] **Карта переклеивает данные ~3 раза в минуту** (проверено). `map_data.js:86`: `setData` без проверки
      изменений, каждый вызов — перекластеризация; отсюда «пропадающие кластеры», обойдённые `try/catch`
      в `map_events.js:93-110`. *Как делать:* сравнивать контент-ключ и пропускать `setData`; после этого
      удалить обход.
- [x] **`refreshStaleSnapshot`** (проверено с уточнением). `runtime_clock.js:108`: в норме 1–2 лишних
      запроса в минуту (все `304`, но каждый запускает полную пересборку), а пока upstream сети лежит —
      запрос каждые 5 с с каждой вкладки, бесконечно; плюс второй такой же ретрай в `:121`.
      *Как делать:* оставить один механизм — 30-секундный опрос — и убрать обе пятисекундные петли,
      либо гасить их экспоненциальной паузой.
- [x] `node_stats.js:163/294` (проверено при исправлении): модель строится каждую секунду ДО сравнения ключа, а ключ
      включает `fetched_at`, поэтому панель пересобирается каждый опрос и сбрасывает скролл. Проверить и
      считать ключ до построения модели.

Оценка: 5–6 ч. Проверять `/workflows`-стилем: до и после — счётчик перерисовок в консоли и профиль вкладки.

## Этап 5. Гонки и три копии одного кэша

Сначала **проверить** — эти пункты из ревизии, мной не подтверждены:

- [ ] `runtime_status.js:7` — статус грузится из 5 мест без счётчика запросов.
- [ ] `round_stats_data.js:15/127`, `node_stats.js:76` — cache/live-ответы в любом порядке, старый побеждает;
      `finally` освобождает таймер, которым может владеть более новый запрос (скопировано в обе панели).
- [ ] `round_stats_data.js:12` — окно свежести кэша (30 с) равно периоду опроса → перезапрос на каждом тике.
- [ ] `runtime_chains.js:71/79` — вкладки пересоздаются дважды за `selectChain` и на каждом опросе; клик по
      уже активной вкладке = повторная загрузка часов.
- [ ] `runtime_clock.js:56` (проверено) — `state.snapshot` присваивается до `await` обновления карты: при
      смене сети без кэша `setError`/`renderChainTabs`/round-stats ждут до 15 с.

Затем — то, ради чего это собрано вместе:

- [ ] **Один кэш вместо трёх.** `state.js:51`: часы / статистика / карта держат по три поля и по своему
      набору функций; блок дедупа in-flight побайтно одинаков, prefetch-цикл с шагом 350 мс — в двух из трёх.
      Различаются только политики свежести — и ровно в них живут дефекты выше. ~200 строк → ~50 + три конфига.
- [ ] **Один загрузчик вместо двух.** `node_stats.js:76` = `round_stats_data.js:93`, включая 180-мс таймер и
      скопированный дефект владения таймером; двухчастная защита от гонки написана 8 раз в трёх файлах.

Оценка: 1–1.5 дня. Делать после этапов 1–3, чтобы рефакторинг шёл по уже исправленному поведению.

## Порядок и почему такой

0 → 1 → 2 → 3 → 4 → 5 → 6. Сначала обвязка (иначе нечем закрепить), потом то, что видит пользователь,
потом корректность при смене сети, потом стоимость (самая большая победа — одна удалённая строка), потом
трафик с деплоем, и только потом рефакторинг кэшей — по уже исправленному поведению. Хвосты — когда удобно.

Оценка целиком: ~3 рабочих дня без этапа 5, ~4.5 с ним.
