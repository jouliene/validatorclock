# Геолокация: готовность экспериментальной версии к переносу

**Итог: код готов к переносу в main после решения владельца проекта.**
На полном наборе нод устранены три крупных ошибки локации, поддержанные измерениями
из разных сетей. Неподтверждённых переносов более чем на 100 км в сравнении не осталось.
Исправлены потеря истории, ложный backoff при паузе сервиса и повторные обращения
при ошибках получения измерений. Двухсуточное обновление проверено на всём наборе.

Это не обещание точно определить каждый город. **29 IP остаются спорными**,
а остальные ответы баз тоже являются приблизительными. Значительного процента
глобальной точности без физической ground truth мы не заявляем. Основание для
переноса — конкретные исправления без новых неподтверждённых крупных перемещений,
проверяемая неопределённость и устойчивое расписание запросов.

Ветка: `experiment/node-geolocation-audit`. Main и production не переключались.
Production при получении снимка: `5cea791dea634b59cdea8959b34bbdad649e8c9c`.
Локальный main: `592a6f23e3921a3e41924253874fa7830bb211a2`.

В каждой поддерживающей сети получены минимум три ответа самого исследуемого IP.
Первый и второй адреса — Latitude, третий — другой оператор (AS18450).
В runtime нет исключений для этих IP или списка разрешённых ASN цели.

Остальные семь результатов измерений поддерживают существующие метрополии:
три Moscow, два Warsaw и две лондонские точки. В последних двух случаях Bexley
укрупняется до London (~18 км); это не записано как исправление ошибки.
Координаты измеренной точки обозначают приблизительную метрополию, не серверную стойку.
Метаданные проб могут ошибаться, поэтому измерения — более сильное свидетельство,
а не абсолютное доказательство конкретного здания или улицы.

**Десять IP `155.2.223.0/24` больше не перемещаются с Кайманов в Amsterdam без
подтверждения.** Старая точка сохраняется с `disputed`, новая версия и причины —
в журнале. Для `.16`, `.28`, `.43` дополнительно получены ответы и измерения, которые
раньше не назначались после отбрасывания старого свидетельства. Точная локация этих
десяти серверов остаётся неизвестной; сохранённые Кайманы не объявляются правильными.

Старый `legacy_refresh` также запущен через локальное воспроизведение тех же ip-api
ответов, с сохранёнными оригинальными IPinfo/tiebreak и их датами. Получились **те же
три крупных отличия**, все поддержанные измерениями. Новые IPinfo-ответы этот replay
не получает, поэтому это сравнение алгоритмов на общих доступных свидетельствах,
а не новый независимый опрос всех старых сервисов. Внешних запросов replay не делает.

## Как работает итоговый код

1. Уже работающий DHT-резолвер отдаёт IP. Новые и поздно найденные адреса попадают
   в очередь. Повторение IP в сетях/сетах не запускает повторное исследование.
2. Успешный результат переиспользуется **двое суток**; после срока выполняется новое
   исследование. Истечение TTL не позволяет повторно продлить старый результат без
   запроса. Ручные локации сохраняют прежний приоритет.
3. ip-api сверяется с локальной DB-IP; расхождение стран или координат >100 км
   вызывает дополнительную проверку ipwho.is. Голосования «два против одного» нет.
4. Предыдущая опубликованная точка хранится отдельно от свежих ответов. Истечение
   свежести не стирает историю. Крупный перенос/смена страны требуют независимой
   проверки даже при согласии нынешних баз. До её результата сохраняется предыдущая
   точка с `disputed`, а актуальные сведения об операторе могут обновляться отдельно.
5. Globalping выбирает доступные города по версиям локации и каталогу проб независимо
   от оператора цели. Пробы в дата-центрах имеют приоритет над сетями доступа, чтобы
   уменьшить влияние последней мили. Для согласованной, но далёкой от доступных проб
   точки также назначается проверка; сама удалённость не доказывает ошибку базы.
6. Для принятия метрополии нужны короткие RTT <=3 мс из двух разных ASN, минимум
   три ответа в каждой, согласованные страна и метрополия (до 100 км). Несовместимые
   короткие ответы оставляют спорность. При единственном поддерживающем ASN разрешена
   одна дополнительная ранее не измеренная сеть. Порог не подгоняется под город.
7. Задания, ответы и неудачи сохраняются. Готовые задания не создаются повторно
   после рестарта. Неудачи POST и GET ждут 1ч → 6ч → сутки → 3 суток → неделю.
   Медленно выполняющееся задание сохраняет ID и также не опрашивается бесконечно
   с пятиминутной частотой. Успешный ответ без ping-откликов — неопределённость, а не
   доказательство другой страны.
8. Короткая пауза сервиса соблюдается внутри обработки; она не считается неудачей IP.
   По умолчанию обрабатывается вся очередь. **Суточных потолков 6/128 и потолка 100 IP
   на цикл нет.** На один запрос ip-api остаётся максимум 100 IP. Добровольные лимиты
   администратора доступны, по умолчанию выключены.

Geofeed Hetzner/Latitude — дополнительные адаптеры официальных файлов. Они не
ограничивают универсальный механизм измерений и не переносят IP просто «в город
его оператора». DB-IP обновляется ежемесячно, успешные geofeed — раз в 30 дней,
каталог проб — не чаще раза в сутки при наличии работы. Файлы не скачиваются на каждый IP.

## Штатный прогон и запросы

Повторный прогон использовал реальный `Engine::refresh`, реальные часы и **настоящие
300-секундные интервалы**. Сроки попыток внутри журнала не переносились вручную.
В начале проверки выявлен прежний потолок 100 IP/цикл: этот запуск был явно остановлен,
ограничение убрано, работа продолжена с тем же сохранённым журналом. Уже обработанные
адреса и оплаченные бесплатной квотой измерения не запускались заново.

Окончательный проход: **05:46:07–05:56:40 UTC**, три цикла, оставшаяся работа
9 → 6 → 0 IP. Использовались недавние наблюдения и 36 завершённых заданий предыдущего
полного аудита. Общие MMDB/geofeed тоже переиспользованы. Это не холодная установка.

| Дополнительные обращения итогового прохода | HTTP |
|---|---:|
| ipwho.is | 3 |
| Новые задания Globalping | 9 |
| Получение результатов этих заданий | 9 |
| **Итого дополнительно** | **21** |

В суммарном журнале двух полных исследований: **127 HTTP, 45 завершённых заданий,
120 проб**, измерения для 39 разных IP девяти ASN. Весь набор из 416 IP прошёл
алгоритм; измерения нужны только части адресов. Данные прежних заданий с реальными
временами сохранены, не выдаются за повторно выполненные новые ping.

Повтор всего набора и повтор после открытия журнала: **0 HTTP**. После окончательного
сбора результатов два дополнительных открытия/проверки: **0 и 0 HTTP**.
Нулевой warm-проход не означает, что спорные адреса никогда не проверятся снова:
полностью исследованные разногласия обновляются раз в неделю.

После сетевого прогона дополнительно исправлен backoff ошибок чтения результатов API;
он проверен локальными тестами, включая внешний `Engine::refresh` и рестарт. Успешные
географические решения от этой правки не меняются; на текущем коде повторены warm-проверки.

Отдельно с production выполнены две проверки доступности (GET начала каталога
Globalping и HEAD файла DB-IP): обе **HTTP 200 без ключей**. База целиком на production
не скачивалась, конфигурация и процессы сайта не менялись. Эти две диагностические
проверки не входят в 21 запрос географического прогона.

## Проверка двух суток и ошибок

[Двухсуточное воспроизведение](two-day-replay.json) использует реальный движок,
415 автоматически размещаемых IP и локальный HTTP-сервер с записанными успешными
точками. Общие внешние источники в этом тесте отключены/отложены. После исправления
изоляции теста финальный прогон сделал **ноль внешних запросов**.

- 575 пятиминутных циклов до 48 часов: ноль запросов IP.
- Перезапуск на 24 часах не сбросил кэш.
- При достижении 48 часов каждый IP запрошен ровно один раз: 5 пакетных запросов.
- Повтор и ещё один рестарт после обновления не добавили запросов.

Это проверка планировщика с управляемым временем, не реальное 48-часовое наблюдение.
Точность геолокации оценивается отдельным сетевым прогоном выше.

Регрессионные тесты дополнительно проверяют: смену/возврат сета и новый IP,
историю старше двух суток, обновление завершённой точки, частично успешные измерения,
предпочтение разных сетей, неверный target/ID, старые ответы, несовместимые короткие
RTT, источник с паузой, неудачные/неоднозначные POST, ошибки GET и рестарт.
Для неразрешённого IP старый и новый код на локальном сервисе делают за сутки
288 против 6 запросов соответственно. Это сравнение ошибок, не общего месячного трафика.

## Готовность и ограничения

| Требование | Проверенное основание |
|---|---|
| Отдельная ветка, без main/production | Локальные коммиты только в экспериментальной ветке; production использовался для чтения |
| Универсальный алгоритм | Нет фильтра ASN цели; реальные измерения девяти ASN, включая исправление AS18450 |
| Бесплатно, без ключей/ручной настройки | Старый enabled-map config загружается с новыми defaults; Rust сам получает файлы; источники доступны с production без ключей |
| Перепроверка через двое суток | Полный replay 415 IP, перезапуск и отдельный тест истечения успешного результата |
| Нет лишних повторов | Warm/restart 0; backoff ошибок POST/GET; сохранённые ID; нет придуманных суточных потолков |
| Нет спекулятивных крупных переносов в сравнении | Все 3 переноса >100 км поддержаны разными сетями; 10 неподтверждённых изменений страны остановлены |
| Проверенный код | Обычные Rust-тесты и opt-in прогоны, Clippy без предупреждений, frontend-проверки, release-сборка |

Ограничения остаются: совместная ошибка баз может не вызвать проверку; не отвечающий
на ping сервер не обязан быть в неправильной стране; метаданные проб могут ошибаться;
точные здания не определяются. Старое место, оставленное с `disputed`, не становится
от этого доказанным. 29 спорных IP не скрыты и не зачтены как исправленные.
Новые проверки могут увеличить трафик относительно недельного кэша main; меньше
повторных ошибок не означает автоматически меньше общего трафика.

Исследование не меняет DHT-резолвер, настройки посетителей или блокчейн-RPC. Новая
геолокация включается автоматически для уже включённой карты; ключ IPinfo больше не
нужен её новому пути. Детальные свидетельства находятся в `geo_cache.research.json`;
формат старой очереди IPinfo-review относится к прежней стратегии. Ручные overrides
работают в обоих режимах. Старую стратегию можно выбрать `research.enabled=false`.

Итоговые проверки текущего кода: **378 Rust-тестов пройдены**, 9 opt-in тестов
не входят в обычный запуск; результаты относящихся к сравнению opt-in прогонов
приведены выше. **13 frontend-тестов пройдены**. `cargo fmt --check`, Clippy
с `-D warnings` и `cargo build --release --offline` завершились успешно.
