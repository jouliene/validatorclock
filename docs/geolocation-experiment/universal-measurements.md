# Универсальные измерения вместо исключения для Latitude

> Исторический этап. Итоговый код и проверка готовности описаны
> в [окончательном отчёте](../geolocation-readiness/README.md).

Runtime больше не содержит списка ASN или городов Latitude для измерений.
Старый `operators.rs` компилируется только в тестах для воспроизведения исторического
аудита. Его результаты не выдаются за результаты нового алгоритма.

## Общий алгоритм

1. IP после DHT, ручные исключения, постоянный кэш и двухсуточный TTL — прежние.
2. Основной ответ ip-api сверяется с локальной DB-IP. При конфликте/отсутствии
   основного ответа используется ipwho.is. Страны или координаты >100 км — конфликт.
3. Дополнительные geofeed Hetzner/Latitude сохранены. Это пока два адаптера
   авторитетных файлов, не условие допуска IP к универсальным измерениям.
4. Когда есть работа, каталог Globalping обновляется не чаще раза в сутки.
   Каталог содержит города, координаты и ASN доступных проб; нет таблицы
   «оператор целевого IP → город».
5. Измерение требуется при конфликте либо когда предполагаемая локация дальше
   100 км от ближайшего доступного города проб в той же стране. Последнее — повод
   исследовать адрес, не доказательство ошибки. При согласии баз и близкой пробе
   измерения не запускаются. Общая ошибка баз поэтому всё ещё может остаться незамеченной.
6. Для версий локации из баз выбираются ближайшие доступные города в соответствующих
   странах: максимум три города, по возможности две разные сети в каждом. В каждом
   сочетании город/ASN запрашивается одна проба и три ping-пакета именно целевому IP.
   ASN целевого сервера не ограничивает выбор. Недостаток проб не компенсируется
   выдуманным городом или переносом по ASN.
7. Задание асинхронное: HTTP POST, сохранённый ID, GET результата на последующей
   попытке (обычно через час). Рестарт не создаёт повторный POST. Получение результата
   ограничено сроком сутки и тремя успешными чтениями; ошибки подчиняются общему backoff.
   При потере ответа POST немедленная повторная отправка запрещена.
8. Для принятия приблизительной метрополии требуются минимум две разные сети проб,
   минимум три ответа в каждой, min RTT >0 и <=3 мс. Города всех коротких ответов
   должны быть в одной стране и не дальше 100 км друг от друга. Проверяются ID
   задания, целевой IP, resolvedAddress, завершённость и возраст результата.
   Противоречивые короткие задержки оставляют `disputed` (возможны anycast/ошибки метаданных).
9. Координаты принятой точки — координаты города пробы, а не стойки сервера.
   Строгий критерий снижает число автоматических переносов, но не доказывает физическую
   локацию: метаданные проб тоже могут ошибаться. Высокий RTT не доказывает другой город.

## Бесплатность и нагрузка

[Официальные лимиты Globalping](https://globalping.io/credits): без регистрации
250 probe tests/час; [схема API](https://api.globalping.io/v1/spec.yaml) описывает
асинхронные задания и метаданные проб. Ключ не нужен, платные кредиты не используются.

Искусственные суточные потолки 6 заданий / 128 HTTP удалены из настроек по умолчанию.
`daily_requests: 0` и `daily_measurements: 0` означают отсутствие локального суточного
потолка. Положительные значения позволяют администратору добровольно задать потолок;
ранее явно заданные значения сохраняют действие. Скрытых ограничений 500/20 больше нет.
Счётчики и добровольные квоты сохраняются до отправки и не сбрасываются рестартом.
429/Retry-After для Globalping блокирует и создание, и чтение заданий. Программа
использует бесплатный доступ без ключа и соблюдает ограничения сервисов.

До шести проб на задание — ограниченный набор сравниваемых городов, а не суточная квота.
Защиту от лишних запросов обеспечивают очередь новых/просроченных IP, кэш, паузы
источников, backoff и сохранение ID заданий. Обработка по-прежнему идёт через существующий
пятиминутный цикл с ограниченным размером порции, без ограничения шестью IP в сутки.

Успешные точки перепроверяются через 2 суток. Неудачи: 1ч, 6ч, сутки, 3 суток,
неделя; полностью исследованные разногласия — недельное обновление. Каталог проб
и MMDB имеют собственные сроки обновления; они не скачиваются на каждый IP.

## Проверка на реальных IP

[Сохранённые запросы, результаты и выбор проб](globalping-comparison.json).
Локальный запуск, production не затронут. Три IP двух операторов, 3 задания,
8 probe tests, 7 HTTP-запросов (каталог + 3 POST + 3 GET). Повтор использует журнал.

| IP | Измерения | Решение нового критерия |
|---|---|---|
| 67.213.125.125, Latitude | Sydney AS931: 0,553 мс; AS1221: 12,197 мс | Не переносить автоматически: только одна сеть <=3 мс |
| 64.34.88.165, Latitude | LA AS174: 1,484 мс; AS906: 1,758 мс. NY: 60,494 / 56,714 мс | Приблизительно Los Angeles |
| 178.63.165.86, Hetzner | Falkenstein AS24940: 0,317 мс; Deggendorf AS215365: 13,627 мс | Нет двух независимых коротких ответов; конфликт остаётся |

Данные Sydney поддерживают предыдущую гипотезу, но не удовлетворяют новому
критерию автоматического переноса. Порог не ослаблялся ради желаемого ответа.
Это проверка работоспособности, а не доказательство превосходства на всей карте.

В этом же отчёте `offline_selection` содержит выбор проб по сохранённым ip-api
и DB-IP для 416 IP. Это проверка охвата алгоритма без сетевых измерений всех адресов;
она не включает ручные исключения, geofeed и третью базу, и не измеряет точность.
Выбраны 30 IP восьми ASN. Повтор live trial сохранил суммарный счётчик 7 HTTP: новых
обращений не было. Каталог содержал 5035 проб.

## Проверки

Проверки: 368 Rust-тестов прошли, пять opt-in исключены из обычного запуска;
новый live trial выполнен отдельно. Clippy без предупреждений.

Обычные Rust-тесты проверяют независимость выбора от ASN цели, разные ASN проб,
неверный IP/ID, старые и незавершённые ответы, отсутствие проб, несовместимые короткие
RTT и сохранение ID задания через рестарт без второго POST. Старые тесты расписания,
48-часового TTL, backoff и лимитов сохранены.

```sh
cargo test --offline
cargo clippy --offline --all-targets -- -D warnings
# Только явный ограниченный live trial; использует существующий локальный журнал:
VALIDATORCLOCK_GEO_AUDIT_DIR=/tmp/validatorclock-geo-audit \
  cargo test --offline globalping_multi_operator_trial -- --ignored --nocapture
```

В main не переносилось. Универсальность означает отсутствие привязки к оператору
цели, а не гарантию определения любого города. Свидетельств значительно лучшей
точности на всём наборе по-прежнему недостаточно.
